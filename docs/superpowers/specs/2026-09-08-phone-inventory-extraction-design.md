# 独立手机号库存与用户中心提取设计

## 背景

当前批量导入会把手机号直接写入 `managed_records`，用户中心又会把没有手机号的记录隐藏成空卡槽。这使手机号无法作为独立库存管理，也无法支持用户在卡槽中反复排除“老号售后”号码后再确认一个成功绑定的号码。

## 目标

- 将手机号批量导入从综合数据导入中分离。
- 手机号库存严格按运营账号隔离。
- 用户中心为当前卡槽提取手机号，并在“未绑定”“老号售后”“已绑定”三种结果之间推进。
- 只有确认“已绑定”的号码才写入对应的数据管理记录。
- 用户中心不允许更换已绑定号码。
- 保留手机号的导入、提取、售后与绑定历史。

## 非目标

- 不改变谷歌号、OP 和 UID 的原有导入规则。
- 不改变六卡槽批次数量。
- 不允许已绑定号码在用户中心被标记售后或替换。
- 不将“老号售后”号码重新放回可用库存。

## 数据模型

新增独立手机号库存表，每条库存至少保存：

- 所属运营账号 `owner_id`
- 手机号、接码链接、到期时间和默认机型
- 业务状态：`available`、`reserved`、`after_sale`、`bound`
- 临时占用的卡槽与业务记录标识
- 导入、提取、售后和绑定时间

用户界面展示的三种中文状态映射为：

- `reserved` → 未绑定
- `after_sale` → 老号售后
- `bound` → 已绑定

`available` 只是库存状态，不作为已提取号码展示给卡槽。手机号在同一运营账号下唯一，重复导入时不新建第二份库存；对尚未绑定的库存更新接码链接和到期时间，已绑定或老号售后记录保留历史不被覆盖。

`managed_records` 保留现有手机字段，用于数据管理列表、编辑和 CSV 兼容。这些字段只在库存号码确认已绑定时同步写入。

## 后台导入

数据管理页面提供独立的“批量导入手机号”按钮和弹窗。格式仍为：

```text
手机号----接码链接
```

弹窗保留 30、60、90、120、150 天的有效期选择，默认 30 天。普通运营账号导入自己的库存；超级管理员导入时也归入当前登录账号，不隐式分配给其他账号。

原综合导入弹窗不再接受两段式手机号数据，但继续支持谷歌号、OP 和综合数据。接口对误格式、空内容和无效有效期返回明确错误。

## 用户中心卡槽规则

服务端生成卡槽的资格仍是：

- 记录归属当前运营账号。
- 谷歌号、谷歌密码和 OP 均非空。
- UID 为空。

是否已有手机号不再影响卡槽资格。前端删除“无手机号即空卡槽”的二次过滤。

卡槽颜色仍由 UID 流程决定：

- 红色：卡槽有记录且 UID 尚未保存。
- 绿色：UID 已保存，卡槽处理完成。
- 灰色：卡槽确实没有可分配记录。

手机号状态在卡槽详情内独立展示，不改变卡槽颜色。保存 UID 是卡槽变绿的唯一条件。

## 提取与状态流程

1. 当前卡槽没有已绑定号码和临时占用号码时，显示“提取手机号”。
2. 用户点击后，服务端在事务中按导入时间、ID 顺序锁定该账号最早的 `available` 号码，将其改为 `reserved` 并关联当前卡槽和业务记录。
3. 页面展示号码、接码链接、到期时间、机型以及“已绑定”“老号售后”两个明确操作。
4. 点击“老号售后”后，该库存号码改为 `after_sale`，保留关联与历史，但清除卡槽的当前临时占用视图；同一卡槽可继续提取下一个号码。
5. 点击“已绑定”后，服务端在同一事务中将库存改为 `bound`，并把手机号、接码链接、到期时间、机型和“已绑定”写入对应 `managed_records`。
6. 一旦已绑定，用户中心隐藏提取和状态变更操作，只读展示已绑定信息。
7. 保存 UID 前必须已成功绑定手机号；保存成功后卡槽从红色变为绿色。

## 并发和一致性

提取号码时使用数据库事务和行锁，只选择当前账号下的 `available` 记录。并发提取必须获得不同号码或其中一个返回库存不足，不得重复分配。

售后、绑定和 UID 保存都校验：

- 卡槽属于当前用户的开放批次。
- 卡槽关联的业务记录也属于当前用户。
- 手机库存与业务记录的 `owner_id` 一致。
- 只有 `reserved` 可转为 `after_sale` 或 `bound`。
- 只有已绑定的业务记录可保存 UID。

任何校验失败时整个事务回滚。

## 异常与页面反馈

- 库存不足：提示“手机号库存不足”，不改变卡槽或业务记录。
- 重复点击：提取按钮在请求期间禁用，服务端仍通过事务保护。
- 状态冲突：页面提示数据已变更并刷新当前批次。
- 未绑定保存 UID：服务端拒绝，前端同时禁用保存按钮并显示原因。
- 已绑定号码：用户中心只读显示，不提供售后或更换操作。

## 迁移与兼容

升级时不把已存在于 `managed_records` 的手机号搬回待提取库存。这些号码按现有记录继续展示，并在用户中心视为已有最终号码，不允许重新提取。

新库存功能启用后，手机号两段式文本只进入独立导入接口。原有综合数据记录和 CSV 格式保持兼容。

## 测试策略

自动化测试覆盖：

- 独立手机号导入的解析、有效期、去重和账号隔离。
- 原综合导入不再接受手机号两段式。
- 无手机号的合格记录仍进入六卡槽。
- 同一账号按时间顺序提取，不同账号不能互相提取。
- 并发提取不会返回同一号码。
- 提取后 `managed_records` 仍无手机号。
- 老号售后后可以继续提取，且售后号码不再返回库存。
- 已绑定后库存状态与 `managed_records` 在同一事务中更新。
- 已绑定后用户中心不允许售后、解除或再次提取。
- 未绑定号码时前后端都拒绝保存 UID。
- 保存 UID 后卡槽变绿，其他手机号状态不影响卡槽颜色。
- 库存不足、重复请求和非法状态转换都返回可理解错误且不留下部分更新。
